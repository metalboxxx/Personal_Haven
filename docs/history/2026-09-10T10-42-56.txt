2026-09-10T10:42:56 — Planning rounds 1–2 and the v1 build of the personal website

Took the project from an empty folder to a working Astro site: three rounds of design
research, a verified inventory of the owner's real projects, a PRD, and a built v1 with
four project writeups. The site builds clean with zero client JavaScript. Nothing is
deployed and the site code is not yet committed.

WHAT WAS DONE

1. Round 1 — design research. Three agents in parallel against one rubric ("catchy but
   functional, not eye-flashing; flashy humility"): design principles with sources; a
   survey of 10 public-figure sites; a survey of 11 ordinary-person sites drawn from a
   Hacker News thread. Condensed into docs/planning/front-end/00-design-summary.md.

2. Local project inventory. Read both sibling repos (EnglishTest_Tutor, Quant_VnStocks),
   their Claude memory directories, and all 20 Quant history logs. Produced
   04-project-inventory.md: what exists, what can be claimed, what must stay private.

3. Round 2 — the PRD. 05-prd.md: scope, Astro + Cloudflare Pages, IA, the signature,
   the writeup format, the four writeups with their headline numbers, the animated
   background, acceptance criteria, and a decisions log.

4. Repo setup. git init on main, .gitignore, CLAUDE.md. One commit (de8a1ef) covering
   all planning documents.

5. v1 build, via subagent. Astro 5 static site: Home (thesis, bio, four writeups with
   results), About, Contact, four writeups at /work/<slug>. Newsreader against Inter,
   warm paper/near-black, one burnt-oxide accent, both themes contrast-verified. Hero
   is a build-time SVG line field from a committed series, static until
   prefers-reduced-motion allows motion. Zero JS bundles.

6. Post-build corrections. The agent hit its runtime limit mid-edit and flagged its own
   problems; fixed: a misattributed tax correction, two joint decisions filed under a
   first-person heading, an overstated claim about the quant pipeline, three invented
   details (a reply-time promise, "an annoying afternoon", an exact ledger figure), a
   guessed PEAD date replaced with the real one from the history logs, a non-matching
   aria-current, and vector-effect on a non-inheriting element.

7. Layout fix. The shell was 64rem while the text measure is 65ch, so text hugged the
   shell's left edge and left a dead zone to its right — the page read as off-centre on
   wide screens. Shell reduced to 50rem so its content box equals the measure, plus
   scrollbar-gutter: stable. Verified by measuring getBoundingClientRect in the browser
   at 1920: shell 552→1352, prose filling all 704px of it.

8. Documentation rewrite. CLAUDE.md reduced to what it should be: purpose, organisation,
   how the documents relate, commands, and what is gitignored. The never-publish list
   moved into 05-prd.md §10.1 where it is authoritative rather than cross-referenced.

KEY DECISIONS

- Recruiters are a constraint, not the goal. An earlier recommendation to optimise for
  them was reversed: the research found that in both cohorts "catchy" came from voice
  and specificity, not visual polish, and for someone not yet known the honest voice is
  itself the trust mechanism.
- Signature: the through-line ("how does the under-resourced thing beat the
  better-resourced one?") stated exactly once on Home, then proven by structure.
- Every writeup uses constraint → decision → what I rejected → outcome. The rejected
  section is non-optional; it is what no other portfolio carries.
- Layout archetype B (benkuhn.net's information shape), not his execution. No site is
  copied for its visual style; the owner rejects plain-colour engineer minimalism.
- Home absorbs Work — four writeups make a separate index a duplicate of the homepage.
- The animated hero is a deliberate, scoped exception to the anti-pattern list, under
  five constraints, recorded in both 00 and the PRD.
- Nothing published from either project repo. Two writeups carry no code link and say so.
- Attribution: long-only and Benjamini-Hochberg + split-half stability are the owner's
  decisions and are written in first person; the Quant 4.0 scale rejection and
  equal-notional-over-Kelly were joint and are written without claiming the idea.

LEARNINGS WORTH KEEPING

- Summaries are not sources. The first two versions of the project inventory were
  written from CLAUDE.md files and memory directories; twenty history logs sat unread.
  Four claims were wrong as a result, and reading the logs later revealed an entire
  second study (PEAD) that no earlier version mentioned.
- Never attribute a finding to the user without evidence. History logs are Claude's own
  session summaries — "diagnosed", "verified", "measured" describe Claude's work in his
  project, not his. One finding was wrongly credited to him and had to be retracted.
- Audit agent-written copy against the attribution rule. The build agent broke it twice
  in prose it wrote, and caught it only in its own closing report.
- Measure, do not eyeball. Two rounds were spent on an "off-centre" complaint: the first
  diagnosis blamed the browser window and was wrong; the second screenshot came from a
  dead dev server showing a cached render. Check a server is alive with
  `curl -s -o /dev/null -w "%{http_code}" http://localhost:<port>/`, then read
  getBoundingClientRect rather than judging from an image.
- A deployed-looking path in a repo is not evidence of adoption. EnglishTest_Tutor was
  described as production on that basis; it is a side project whose approach was
  dropped in favour of manual data entry.
